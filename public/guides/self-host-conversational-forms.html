OPENFORM / PRACTICAL GUIDES

How to self-host a conversational form builder

Run Openform with Docker or Node.js, protect the owner workspace, and back up your SQLite responses.

By the Openform project · Updated November 17, 2026

Start with the right deployment model

GitHub Pages can host the interactive demonstration, but it cannot run the SQLite-backed API. To collect submissions centrally, deploy the included Node.js service on your own server.

Run with Docker

git clone https://github.com/arjunkshah12345-hash/openform.git
cd openform
docker compose up --build -d

Open http://127.0.0.1:3001. Docker persists your database in the openform-data volume. The compose file binds to localhost by default.

Or run with Node.js

npm ci
npm run build
npm start

Use Node.js 22.13 or newer. Configure HOST, PORT, and DATABASE_PATH for your environment. Local development uses npm run dev.

Protect the workspace

Openform currently has one owner workspace and no built-in login. Before exposing the service, put authentication in front of the workspace and all /api/forms routes. Allow respondents to reach public form pages, /api/public/forms/*, and required static assets. Use HTTPS. Test that an unauthenticated visitor cannot read the owner API.

Publish and test

Create a form, add questions, preview the flow, and publish it. Open the public link in a separate browser, submit a response, then check the owner response table and CSV export. Verify required-field, email, and choice validation.

Back up the database

Use SQLite’s backup command, or stop the service before copying the entire data directory. A running database may use WAL and SHM files; copying only its main file while it is writing can produce an incomplete backup. Test restoring backups before relying on them.

Keep it maintained

Pull reviewed changes, run the tests and production build, preserve your data volume, and restart. Do not publish your local database or environment secrets in Git.
